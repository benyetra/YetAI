# Build 2026-11-18: proven picks and honest yardsticks

Branch `fix/proven-picks-and-honest-yardsticks`. Background: `docs/projection-review-2026-11-17.md`.

## The short version

- No model here beats the betting line today. Nothing in this build changes that, and nothing in it
  promises a profit.
- What changes: an auto pick is published only when it has positive expected value at the real price
  **and** its market has first proved itself on a record measured at real prices. The boards follow
  the same rule. The daily review now measures the right things.
- **Expect zero auto picks for at least the first ~10 NBA slate days, and possibly for much longer.**
  That is the correct result while no market has shown an edge. It is not a bug.

## What changed, per area

| Area | What changed |
|---|---|
| Picks (selection) | Bets are ranked by expected value at the real price (rule `ev-v1`), not by projection-minus-line. A bet needs consensus EV >= 0 and blended EV > 2%. Stale lines (older than the latest NBA refresh, or 3 h) and low-sample players are never picked. Runs moved to **13:30 and 18:00 ET**. |
| Record gate | Records use real prices only (never an assumed -110), the current model version only, and no cap on sample size. A market opens only after **100 qualifying priced calls over 10+ slate dates at ROI >= 0**. `AUTO_PICK_REQUIRE_PROVEN_RECORD` now defaults to on. |
| Boards | One rule for every board: a market the gate withholds shows no pick, side, edge, "Best edges" entry or Gamble It button, with the note "No pick: this market has not proved itself against the line yet". Projections and lines stay. The board no longer invents a side from projection vs line. |
| Daily review | Prob CLV is now fair close vs fair at pick time. MAE is compared to the line on lined rows only. Each market shows its current model version and its record since that version. The bets record is auto picks only, by game date. The gate table lists every key with dates, unpriced count, selection version and reason. New: whether the serving NBA points/rebounds/assists model is below the line (from the retrain's gate record). |
| Training | A retrained prop model is promoted only if it beats the stored line on held-out lined rows and beats the live model by more than noise. Rejections keep the live model and write `<model>_gate.json`. The retrain workflow is green on a rejection and red on a real error. |
| NBA model | Feature version 4 adds who-is-playing information (teammates out, minutes share, expected minutes, return from absence) built the same way in training and serving. Unknown game lines are now "missing", not 0. Live models are still version 3 and are served version 3, so **projections do not change until a v4 model passes the line gate**. Players with 1-4 games this season now get a projection, flagged `low_sample` (never picked). One extra NBA refresh at 18:30 ET for late scratches. |
| NFL / NHL | NFL spread and total are anchored to the market and show no side until a record proves in. Receiving yards and anytime TD show probabilities, no picks. Every NFL/NHL writer freezes at kickoff. NHL morning run writes only today's games; afternoon NHL refreshes every two hours. Every beat job now has an expiry so a killed worker cannot run it a day late. Second pass (`20261118_game_best_price`): NBA and NFL game lines and NFL / NHL props are priced from a stored same-line consensus and can prove in (table below). |

## What you will see in production

**The day after deploy**
- Auto picks: **none**. `auto_pick_runs` rows at 13:30 and 18:00 ET (not 11:00 / 17:30). Drop reasons
  are mostly `unproven_record`, `negative_consensus_ev`, `no_consensus_price`, and `stale_line` if a
  refresh runs late.
- Boards: **no pick labels on any market**, every sport. Projections and lines are all still there,
  with the "not proved yet" note in the Pick column. "Best edges" shows "No picks today".
- NBA projections: the same numbers as before for established players (v3 models). New rows for
  players with 1-4 games, flagged low-sample.
- NFL spread/total cards: numbers close to the line, no HOME/AWAY/OVER/UNDER. No kicker rows in the
  off-season.
- Daily review email: the first section is "what changed / needs attention". Expect it to say the
  NBA models are worse than the line, and to list every gate key as withheld.
- Odds API spend: close capture now asks for all 7 NBA prop markets (about +37 credits on a 7-game
  night, +75 on a 15-game night) plus one more NBA refresh at 18:30. The NHL morning run spends
  about 40-80 fewer.

**Over the next two weeks**
- Only rows written after the migration carry a consensus fair price, so the priced shadow record
  starts from zero on deploy day and grows by each night's qualifying rows.
- **Which markets can / cannot be auto-picked** (second pass: game lines and NFL / NHL props now carry
  a stored best price and a same-line consensus fair probability, `best_*`; moneylines on the two
  spread tables carry `ml_best_*`). A market can prove in only when its rows carry that price, because
  the priced record grades nothing else. Each needs 100 qualifying priced calls over 10+ slate dates at
  ROI >= 0 on its current model version.

  | Market | Can prove in now? | Why / what the EV rests on |
  |---|---|---|
  | NBA points, rebounds, assists, threes, steals, PRA | Yes | Stored best price + consensus; EV = consensus + a small model share (`ev-v1`). |
  | NBA spread | Yes | Same-line consensus (>= 3 other books at exactly the stored line) + model share from the anchored margin. |
  | NBA moneyline | Yes | `ml_best_*` consensus + model share from the margin vs the margin the spread implies. |
  | NBA total | Yes | Consensus only; the model share is 0 (no totals probability model). It passes only when the best book beats the consensus by more than 2%. |
  | NFL spread, moneyline | Yes | As NBA. |
  | NFL total | Yes | Consensus only (model share 0). |
  | NFL passing yards, receiving yards | Yes | Consensus only (model share 0): a price better than the market's fair price is the only edge claimed. |
  | NHL saves, NHL team total | Yes | Consensus only (model share 0). |
  | NBA blocks | No | No stored line column. |
  | NHL shots | No | Books are captured, but there are no `best_*` columns, so no priced record. |
  | NFL anytime TD, kicker | No | No stored line or price. |
  | MLB (game lines, strikeouts, hits), WNBA (all) | No | Their tables have no `best_*` columns and their writers do not attach one (see the spring note). |
  | NHL spread / puck line | No | No projection rows. |
  | NHL moneyline | No | Prices are captured (one bulk call per NHL run) for the review and a later model, but no NHL win-probability model exists, so there is no source. |

  Rows written before this build have no consensus: they stay `withheld-unproven` (`unpriced` in the
  gate table) and the priced record starts from zero on deploy day. "Can prove in" does not mean "will":
  with no edge, a market clears the 100-call floor about a third of the time.
- Monday's NBA Weekly Retrain will most likely reject every candidate as "rejected by line". The
  run should be green with a table of notices. The live models keep serving.
- If a market does prove in, picks appear only for that market, only at +EV prices, at most 3 a
  day (2 per market, 1 per game). A market that proves in can still lose: 100 calls is a floor, not
  proof (a market with no edge passes it about a third of the time).

## Migrations (one line, one head: `20261118_game_best_price`)

Run by the deploy workflow (`alembic upgrade head`) before the API and worker deploy.

1. `20261118_prop_best_fair_ev` (after `20261115_fair_price_shadow`): nullable `best_fair_prob`,
   `best_ev`, `best_quoted_at` on the 7 NBA prop tables.
2. `20261118_nba_prop_low_sample`: nullable `low_sample` on points, rebounds, assists, threes,
   steals.
3. `20261118_nhl_goalie_uq`: deletes duplicate live NHL goalie rows (keeps the newest per date and
   team), then a partial unique index. The deleted duplicates are not restored by a downgrade.

4. `20261118_game_best_price` (after `20261118_nhl_goalie_uq`): nullable `best_book`, `best_line`,
   `best_price`, `best_side`, `best_fair_prob`, `best_ev`, `best_quoted_at` on the NBA and NFL
   spread and totals tables, the NFL QB and receiving yards tables and the NHL goalie saves and
   team totals tables (8 tables), plus `ml_best_book`, `ml_best_price`, `ml_best_side`,
   `ml_best_fair_prob`, `ml_best_ev`, `ml_best_quoted_at` on the NBA and NFL spread tables.

All four add nullable columns or an index, use `lock_timeout 5s` where they alter big tables, and
were run up and down on sqlite in tests. They were not run on Postgres here.

1. Deploy runs migrations first. Confirm: `alembic current` shows `20261118_game_best_price`.
2. Railway env: unset `NBA_CLOSE_CAPTURE_MARKETS`, `AUTO_PICK_RECORD_PRIOR_MAX_PICKS`,
   `AUTO_YETAI_PICKS_MIN_SCORE` if present. Keep `AUTO_PICK_REQUIRE_PROVEN_RECORD=true`.
3. NFL receiving-yards repair, **dry run first**:
   `cd backend && python -m app.services.etl.nfl.repair_recv_week_2026_11_10` (prints what it would
   delete). Add `--apply` only after reading the output; it deletes rows for good.
4. Gate state: `cd backend && PYTHONPATH=. python -m app.services.auto_pick gate` against a read
   replica. Expect every key `withheld-unproven`.
5. Retrain per stat (points, rebounds, assists): GitHub **NBA Train Prop Models** with
   `start=2024-10-01`, `end=<yesterday>`, `cache=true`, `upload=false` first. Upload only through
   the gate. Expect "v4 beats v3 by about 1% and still loses to the line": that is a pass of the
   process, not a failure.
6. Next morning's daily review: read "needs attention", then the gate table (every key, `n`, `dates`,
   `unpriced`, `reason`), the "NBA <stat> model" lines (below line / not below / unknown), and the
   current-model MAE vs line MAE. The bets record should show no new auto picks.
7. After the first slate: closes captured for every NBA prop market (query in the yardsticks
   handoff), and `max(projected_at)` for today's points rows lands before 13:30 and 18:00 ET.

## Deploy order

- The deploy workflow runs `alembic upgrade head` first and deploys the API and worker only if
  it succeeds. **The new code must not start before the migrations**: every query on the NBA
  prop tables would fail (missing columns), and so would the NBA / NFL spread and totals, QB,
  receiving and NHL goalie / team-totals writers and sources (the `best_*` columns of
  `20261118_game_best_price`; same rule as #191). Old rows have no consensus and stay
  `withheld-unproven` (`no_consensus_price` on a run). So no manual `railway up`, no service redeploy of a
  new image, and no retrain workflow run from this branch against production before the
  migrate job has run.
- Old code after the migrations is fine (new columns are nullable), with one small exception:
  in the minutes between the migration and the new worker, an NHL goalie starter change in the
  old writer can hit the new unique index and fail that one NHL refresh. It recovers on the
  next run.
- The migrations give up after 5 s if a pipeline holds a table, which fails the deploy safely.
  Merge outside the refresh windows (12:00, 17:00, 18:30 ET for NBA; :45 of even hours for NHL;
  NFL game days Sun 10:00 / 12:30 / 15:30, Mon 17:00 / 18:15, Thu 10:00 / 17:00 / 19:00, Sat 12:30).
  `20261118_game_best_price` alters 8 of these tables in one transaction.
- The roll-back rule below covers all four migration files. Do not upload a v4 model before this code is live: old code would serve it with v3 inputs.

## How to roll back

- **Do not just redeploy the old `main` commit**: its deploy workflow would run the old tree's
  `alembic upgrade head`, which does not know the new revisions, so the migrate step fails and
  nothing deploys. Instead revert the merge on `main` but keep the four migration files in the
  tree (`git revert -m 1 <merge>`, then restore `backend/alembic/versions/20261118_*.py` and
  commit). The old code ignores the new columns and index.
- Only if the columns themselves cause trouble, from the new tree:
  `alembic downgrade 20261115_fair_price_shadow` (drops the new columns and the goalie index; to remove only the game-line columns,
  `alembic downgrade 20261118_nhl_goalie_uq`; the
  deleted duplicate goalie rows do not come back), then deploy the old code.
- Kill switches that need no deploy: `AUTO_YETAI_PICKS_ENABLED=false` (no pick runs),
  `NBA_PREGAME_REFRESH_ENABLED=0`, `NHL_PREGAME_REFRESH_ENABLED=0` (refresh spend).
- Do not "roll back" by setting `AUTO_PICK_REQUIRE_PROVEN_RECORD=false`: that reopens unmeasured
  markets on the boards.

## Known limits (not fixed in this build)

- The v4 "teammates out" features are learned from who actually played and served from the
  injury report, so their effect may be weaker live than in training. A v4 model still needs to
  beat the line to be promoted, and then its new model version must prove in on live prices
  before it can pick.
- The board recomputes the gate on every request (90 days of rows). Fine at today's traffic;
  cache it per day if the board gets slow.
- The shadow record grades each row at its last price of the day and counts every qualifying
  row, not only the 3 a day that could be picked. It is a proxy for the picks.
- NFL receiving-yards rows still carry `p_over` (a probability, like P(TD)), shown with no pick.
- Game lines and NFL / NHL props: the shadow record grades each row's LAST pre-game write, which is
  not always the write the 13:30 / 18:00 run saw (the NBA 18:30 refresh rewrites rows after the last
  run; an NHL game after about 21:00 ET is refreshed only after 18:00, so it is never fresh at a run
  but still counts in the record). Same proxy as the NBA props; the 10-date floor and the live-book
  rule are the guards.
- With k near 0 the side of a game-line candidate is set by the anchor's constant correction, not
  by the model, and EV comes from price vs consensus only. These are price picks, not model picks.
- EV at whole-number spreads and totals ignores the push probability (slightly high at NFL 3 / 7,
  NHL 5 / 6), as the prop path does.
- The best book must be live: seen by the newest fetch and updated within 5 minutes of the
  freshest book (`consensus_price.BEST_SEEN_GAP` / `BEST_MAX_LAG`); the consensus books may be up
  to 30 minutes old. A book that pulled its market is never the price.
- Pending-approval mode: the NFL Mon 18:15 and Thu 19:00 refreshes make an 18:00 MNF / TNF pick
  unapprovable after 15 / 60 minutes (the same stale rule as NBA's 18:30).

## Odds API credits per day

The consensus price reads the `odds_line_snapshots` rows that every `sync_odds_get` odds response
already records, so most of it costs nothing. Billing is markets x regions, and 10 books or fewer is
one region (`PROP_BOOKS` is 10).

| Change | Credits |
|---|---|
| Widen books to the 10 `PROP_BOOKS` on calls already made (NFL game lines, NFL passing and receiving yards per event, NHL event odds) | 0 |
| NBA game lines (one bulk call, 10 books, already) | 0 |
| NFL game-day game lines (bulk, 3 markets: spreads, totals, moneyline) | +3 per run; 9 runs a week (Sun 3, Mon 2, Thu 3, Sat 1 runs) = +27 a week (Sun +9, Mon +6, Thu +9, Sat +3) |
| NHL moneylines (bulk h2h, 1 market) | +1 per NHL run (05:00 plus up to 6 refreshes) = at most +7 a day |

**Added in total: at most about 16 a day on an NFL Sunday (+9 NFL game-day, +7 NHL), about 7 on other
days.** The estimate this sits on: the whole system burns about **320-460 a day**
(`docs/reviews/2026-11-17/nhl_and_infra.md` section 6: NBA 150-185, NHL 80-140, NFL 50-100, games
cache ~36), against the 500 a day cap (`ODDS_API_DAILY_BUDGET`), so this build uses about 2-5% of the cap
and the plan still lasts to the 12-14 reset. At the top of that estimate an NFL Sunday reaches about
476 of 500, so the cap can bite on a heavy Sunday: the guard then refuses calls and those rows get no
consensus price (no pick), never a guessed one. That estimate is itself a HYPOTHESIS from the schedule,
not a measurement: check the 09:45 ET email's credits section (it needs Redis, so it is empty on the
GitHub runner) or `GET odds:budget:credits:<UTC day>` the day after an NFL Sunday.

Left out on purpose:
- No extra calls for NHL player shots, NFL anytime TD, MLB or WNBA (no `best_*` columns to fill).
- No per-book or per-line calls: a book at another line is never converted into the line (no validated
  conversion for these markets), so a price from a book at a different line is simply not used.
- The NFL weekly pipeline (`NFL_PHASES`) is unchanged; only the game-day pipeline got a `game_lines` phase.
- The cap is not raised and the UTC-day reset (19:00 ET) is not moved; the review's warning about
  evening jobs being last in line when the cap is hit stands.

## Spring note: MLB and WNBA

Nothing for MLB or WNBA is in this build. To switch them on later: add the `BestQuoteColumns` to the
WNBA spread and totals tables (and the MLB game-lines and strikeouts tables) with a migration, attach
`best_*` (and `ml_best_*` for moneylines) in their projectors the way `etl/_consensus_attach.py` does for
the NBA and NFL writers (one shared side rule, same-line consensus), make their sources read it, and add
their loaders to `record_gate.PROJECTION_LOADERS` and keys to the board map. Until then their keys have
no priced record and stay withheld under prove-in.
